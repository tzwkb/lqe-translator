## 2. 测试目标

本测试集验证：

1. Terminology issue 只能通过结构化字段表达术语和跨度。
2. span 形状、排序、范围和文本切片严格正确。
3. 原文、原译和建议译文的红字/删除线符合优先级。
4. 无建议、漏译和整段删除不会混淆。
5. 第 2 轮及后续报告使用对应轮次的送审译文。
6. 单任务、历史 Scorecard 和聚合报告结果一致。
7. 旧术语产物失败关闭，并能从 `pre-check` 安全恢复。
8. 无术语模式不会因新字段或报告逻辑重新启用术语检查。
9. corrected 文件保持纯文本。

## 4. 公共测试数据

### 4.1 标准术语问题

```text
source         = 查看督管案台
current_target = Check the control desk
term_source    = 督管案台
expected       = Supervisor's Counter
source span    = [2, 6)  督管案台
target span    = [10, 22) control desk
```

对应 issue：

```json
{
  "category": "Terminology",
  "severity": "Major",
  "comment": "Use the approved term.",
  "needs_confirmation": true,
  "edit": null,
  "term_source": "督管案台",
  "expected_targets": ["Supervisor's Counter"],
  "term_spans": {
    "source": [{"start": 2, "end": 6, "text": "督管案台"}],
    "target": [{"start": 10, "end": 22, "text": "control desk"}]
  }
}
```

### 4.2 迭代问题

```text
initial target = Check the control desk
Iter 1 target  = Updated prefix: Check the control desk
Iter 1 span    = 以 Iter 1 target 中 control desk 的实际位置计算
```

### 4.3 漏译问题

```json
"term_spans": {
  "source": [{"start": 2, "end": 6, "text": "督管案台"}],
  "target": []
}
```

## 6. 待补自动化覆盖

以下行为已有实现或产品口径，但尚缺直接、独立的自动化断言：

1. 同一 Segment 有两个 Terminology issue：Results 取并集，Scorecard 每行只标自己的 span。
2. `term_spans.target=[]` 的完整报告只标原文，不把原译整句标红。
3. Unicode 术语 span 本身落在组合字符或 emoji 字素簇中的显示行为。
4. 带 source/target span 的公式样术语文本。
5. 超过 32767 字符时，术语高亮明确退化为纯文本。
6. 聚合报告中 source 红字、多术语并集和 Scorecard 逐问题隔离。
7. 无术语模式报告单元格不存在任何术语红字的直接富文本断言。
8. `tests/test_documented_contract.py` 对新 span 合同、红字图例和旧任务重跑说明的显式断言。

这些是测试覆盖缺口，不应被表述为“已验证”。
