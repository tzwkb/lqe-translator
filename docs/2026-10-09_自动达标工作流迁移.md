# 自动达标工作流迁移

新增可选的自动达标流程。普通审校、optimized/full 和参考建议的原有语义保留。
程序实现与真实模型质量、速度验收分别记录。

2026-10-10更新：当前政策以文末“门槛优先与测试预算”为准；此前严格争议门槛及实测
记录属于旧冻结任务，不能据此将旧任务改记为通过。

## 共用核心和适配

`scripts/lqe_workflow_core/` 是问题状态、检查计划、阶段决策、验收条件和恢复日志的
唯一维护来源。集成服务使用带版本与逐文件摘要的固定副本，通过
`scripts/sync_workflow_core.py --integration-root <集成仓库> [--check]` 同步或核对。
网页、权限、队列和服务执行适配器仍留在集成仓库。

原模块适配器保留 native state、原文件定位、项目资料、审校凭据及评分函数。
中间阶段只派发选中句段，完整文档仍作为上下文；最终检查与导出覆盖全文。
原生 SDLXLIFF/XLIFF 导出、标签和锁定段保护不转换为 Excel 后替代。

## 使用

完整协议见 `references/automatic_workflow.md`。先以原有 read 建立 full 新任务：

```sh
python3 scripts/lqe_workflow.py init --workdir /absolute/workflow \
  --state /absolute/native-job/state.json --runtime-config /absolute/runtime.json
python3 scripts/lqe_workflow.py run --workdir /absolute/workflow
python3 scripts/lqe_workflow.py verify --workdir /absolute/workflow
python3 scripts/lqe_workflow.py report --workdir /absolute/workflow
```

`worker_command` 是模型执行器的 JSONL 接口，不绑定新供应商；现有 Agent 也可以使用
next/submit。编排进程可跨轮保留，检查者身份及最终判断必须独立。过程包不包含原始运行配置。

## 时间与恢复

- 程序准备文件、制定计划和流转状态，减少主 Agent 重复安排流程。
- 中间阶段缩小检查范围，复用有有效证据的未变结果。
- 中间阶段不重复生成整句参考建议和正式工作簿；问题证据完整保存，过程报告按需生成。
- run 保留编排进程；模型适配器负责复用安全的资料初始化，终审仍使用新检查者。
- 记录准备、阶段完成与验证用时；不能用夹具测试耗时宣称业务提速。
- 同一响应重复提交不会重复修改；恢复先检查原稿、项目资料及运行配置是否变化。

处理；这不代表模型质量或真实业务速度已经验收。

## 首次实测发现与修复

此前234段真实业务测试执行9阶段，墙钟6小时08分52秒，包含主机睡眠和开发恢复等待。
工作分曾达98.35，独立全量终审降至93.41，系统正确返回自动修正；最终工作分98.53仍有
待核对问题，触发停止，未开放最终交付。保存160条问题和131条修改记录。这个结果不能
作为自主达标或整体提速证明。

实测发现，已解决问题复发时，旧计数把历史成功修正也占用新的失败预算。共用核心1.0.2
保留历史累计 `attempts`，用 `attempts_since_resolution` 记录当前未解决过程；只有明确
解决或有证据撤销后再次出现才重置，漏报或争议不重置。两侧使用相同规则，连续三次仍未
解决的停止保护保留。只读重放9阶段后，160条问题的判断与历史累计次数不变，原触发
耗尽的问题当前未解决次数实际为1。集成侧另修复局部复查成功后未更新停滞计数的问题。

重复核对同一争议时，每次独立证据均保留，证据与调用者对象隔离。路径带空格的修复仅
涉及原模块收尾脚本的可执行路径引用，不改变评分、检查范围或验收规则。
